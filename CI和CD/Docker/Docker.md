# Docker是什么？
Docker 本质上是一个**容器化（Containerization）平台**，它能够将应用程序及其运行环境（代码、依赖、配置、系统库等）打包成一个**容器（Container）**，然后在任何安装了 Docker 的机器上运行，并且保证运行结果一致。

理解：将环境和应用一同打包形成镜像共别人使用和运行

**Docker = 应用打包 + 应用隔离 + 应用运行平台。**

1. 镜像：应用模板，比如 数据库、代理、SDK等等开发所需的中间件和软件包
2. 容器：指的是进行运行起来的实例，比如：当一台电脑上安装了一个数据库，那么这台电脑就可以叫做一台容器
3. Docker Engine：Docker的运行时，负责创建容器、删除容器、下载镜像、网络、存储、日志

---


# 特点
1. 轻量级：共享宿主机的所有内核
2. 环境一致
3. 隔离性：每个容器的文件系统、网络、端口、进程隔离
4. 可移植：导出镜像即可迁移
5. 启动快：不需要启动完整的操作系统

# Docker能干什么？
1. 部署应用
2. 部署数据库
3. 微服务

# Docker和虚拟机的区别

|对比项|Docker（容器）|虚拟机（VM）|
|---|---|---|
|虚拟对象|应用及其依赖|整个操作系统|
|是否包含操作系统|不包含完整 OS，共享宿主机内核|每个 VM 都有完整 OS|
|启动速度|秒级甚至毫秒级|通常几十秒到几分钟|
|资源占用|较低|较高|
|隔离性|较强，但共享内核|更强，内核完全独立|
|性能损耗|很小|相对更大|
|典型用途|应用部署、微服务、开发测试|多操作系统、强隔离环境|


一个完整Docker使用流程：
```
编写代码
    │
    ▼
编写 Dockerfile（描述如何构建镜像）
    │
    ▼
docker build（生成镜像）
    │
    ▼
Image（应用模板）
    │
    ▼
推送到镜像仓库（可选）
    │
    ▼
docker pull（在目标机器获取镜像）
    │
    ▼
docker run（启动容器）
    │
    ▼
应用开始对外提供服务
```

**Dockerfile的作用：** Dockerfile 定义了镜像的完整构建流程(描述如何构建镜像)，保证环境一致，可以版本管理，支持自动化部署（CI/CD）

# 数据卷
Docker 数据卷（**Volume**）是 Docker 中最重要的概念之一，它主要解决两个问题：

1. **容器删除后数据如何保存？(将数据与容器实例隔离)**
2. **容器如何与宿主机共享文件？**

一句话概括：

> **数据卷（Volume）就是 Docker 提供的一种独立于容器生命周期的数据存储机制**

特点：
1. 生命周期独立
2. 多个容器共享
3. 数据持久化
4. 性能好

# Docker 中的数据存储方式

Docker 一共有三种常见的数据存储方式。

1. Volume（推荐）
2. Bind Mount（宿主机目录挂载）
3. tmpfs（内存挂载）

# Volume 和 Bind Mount 的区别

|对比项|Volume|Bind Mount|
|---|---|---|
|数据存放|Docker 管理|用户指定目录|
|是否依赖宿主机目录|否|是|
|是否容易迁移|是|相对差|
|是否方便查看文件|一般|非常方便|
|是否推荐生产数据库|是|是（也很常见）|
|是否推荐开发|一般|非常推荐|
# 多容器编排
Docker Compose 是 **Docker 官方提供的多容器编排工具**，用于**通过一个配置文件统一管理多个 Docker 容器**。

一句话概括：

> **Docker 管一个容器，Docker Compose 管一组有关联的容器。**

如果说：

- **Docker** 负责"创建一个容器"
- **Docker Compose** 负责"管理整个项目"

**Docker Compose 与 Docker 的关系**

可以把它们理解成不同层次的工具：

|Docker|Docker Compose|
|---|---|
|管理一个容器|管理多个容器|
|使用 `docker run` 启动|使用 `docker compose up` 启动|
|手动配置网络、数据卷|自动创建网络和数据卷|
|适合单个服务|适合完整项目|
|命令式（一步一步执行）|声明式（写配置即可）|
